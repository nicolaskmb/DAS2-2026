# ADR-002: Adoção de Azure SQL Database como armazenamento estruturado analítico da solução

**Status:** Aceito  
**Data:** 2026-04-06  
**Autores:** Nicolas, Jorge, Thales, Vladimir

---

## Contexto

A plataforma da VendaMais deve armazenar os dados extraídos do ERP de forma estruturada, rastreável e historizada, permitindo transformações, consultas analíticas e consumo por dashboards no Power BI.

A arquitetura proposta define duas camadas complementares de persistência: Azure Blob Storage para arquivos brutos, e Azure SQL Database para dados tratados e normalizados, servindo como fonte única de verdade para relatórios.

Os requisitos do projeto incluem:
- Persistência estruturada em nuvem  
- Rastreabilidade e histórico dos dados  
- Tabelas analíticas limpas e confiáveis  
- Dashboards com atualização diária  
- Facilidade de manutenção futura pela equipe  

---

## Decisão

Foi decidido adotar o **Azure SQL Database** como repositório estruturado principal dos dados tratados e normalizados, mantendo o **Azure Blob Storage** como armazenamento complementar para arquivos brutos (raw).

Essa decisão foi tomada porque o modelo relacional do Azure SQL permite consultas analíticas mais eficientes e integração direta com o Power BI, atendendo melhor às necessidades de relatórios e KPIs.

Além disso, comparado às alternativas, o uso de um banco relacional gerenciado reduz a complexidade operacional (em relação a VMs) e oferece melhor suporte para análises estruturadas (em relação a Blob Storage e bancos NoSQL).

Na prática:
- **Azure Blob Storage:** responsável por armazenar dados brutos e históricos  
- **Azure SQL Database:** responsável por disponibilizar dados estruturados para análise  

---

## Consequências

### (+) Benefícios

- Facilita consultas analíticas e integração com Power BI  
- Melhora a organização, consistência e governança dos dados  
- Define uma fonte única de verdade para indicadores  
- Mantém rastreabilidade ao utilizar Blob Storage como apoio  
- Permite reprocessamento dos dados quando necessário  

### (-) Pontos negativos

- Custo maior em comparação a soluções baseadas apenas em arquivos  
- Necessidade de modelagem relacional e maior esforço inicial  
- Dependência de serviços gerenciados da Azure (vendor lock-in)  

---

## Alternativas rejeitadas

- **Uso exclusivo de Azure Blob Storage:**  
  Rejeitada por não ser ideal para consultas analíticas complexas e estruturação de dados para dashboards.

- **Banco de dados em máquina virtual (VM):**  
  Rejeitada devido à necessidade de gerenciamento de infraestrutura, backups e manutenção manual.

- **Banco NoSQL como armazenamento principal:**  
  Rejeitada por não atender bem a necessidade de análises relacionais e consultas estruturadas exigidas pelos KPIs.
